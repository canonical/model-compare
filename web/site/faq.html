FAQ

Short answers to the questions the tables raise: which models appear, how prices and quality are picked, and why the numbers can differ from OpenRouter. For setup and routing guides, head over to How to use.

What do PREC and the "!" marker mean?

On OpenRouter, a single model name isn't necessarily tied to one company's servers. Several backend providers ("endpoints") can host the exact same open-weight model at different prices and compression levels.

That compression is called quantization: converting a model's high-precision weights (such as bf16) into smaller number formats (such as fp8 or int4). It cuts memory use and speeds up replies — though pushing it too far can chip away at answer quality.

Rather than taking OpenRouter's headline number at face value, model-compare checks every live endpoint for a model and ranks it using the cheapest eligible one that meets (or beats) the model's baseline precision. In the ZDR view the quote also has to come from a zero-data-retention endpoint that advertises the required tools and prompt context and passes OpenRouter's endpoint-policy gates (BYOK, moderation, deranked and training). The PREC column shows the model-level baseline precision across its live non-variant endpoints — the maker's highest disclosed format, or the best available when the maker discloses none; n/a means nothing is known. PREC is not necessarily the precision of the endpoint that sets the price, and it is the same in both views.

A trailing ! (for example, fp8!) is a rough heads-up, not a traffic measurement. It compares how cheap the lower-precision endpoints are with the eligible ones. When the cheaper side wins that comparison, ! appears. No ! is not a guarantee: OpenRouter can still route some calls to a cheaper endpoint.

The upshot: without routing rules, your calls can quietly land on a more heavily compressed version of the model than the row describes. Hover the PREC cell (or click the row) to inspect the competing endpoints, their precisions, and their prices — and see How to use for how to lock routing down.

Why does PREC say n/a?

It means no live provider disclosed a recognized number format. That does not automatically remove the model. An endpoint run by the model maker, or by an official partner host, can still set the baseline when its format is unknown. A third-party endpoint with an unknown format cannot.

n/a means no live endpoint in the derivation universe disclosed a recognized format. It is a gap in the data, not a claim that the model runs at full precision.

Why can the price I pay differ from the ranked price?

If you compare a row here against the model's page on openrouter.ai, the two prices often won't match. That's by design: OpenRouter's page shows its default route and headline price, while this site quotes the cheapest eligible standard-tier endpoint that meets the model's baseline precision. Faster priority or ultrafast tiers are never used, and Flex is only used when the ranking explicitly asks for it.

Endpoint policy is part of eligibility too. A BYOK-only endpoint is skipped unless you pass --byok, a deranked endpoint is skipped while a better default route exists, and an endpoint whose provider trains on prompts is not quoted under the default ZDR mode.

To judge overall value for money, model-compare blends input and output prices at a 75% / 25% split. Coding sessions tend to send plenty of file context in and get comparatively short patches back, so weighting input heavier reflects real usage much better than a 50 / 50 average.

In practice, three things can nudge your actual bill away from the table price:

  • Default routing: if you don't pin your provider list, OpenRouter may route a call to a pricier (or cheaper) backend than the one ranked here.
  • Long-context tiers (TIER shows >200k, >272k, and similar): some providers charge more per token once a conversation grows past a prompt-size threshold. To avoid bait-and-switch starter rates, model-compare evaluates prices at a 1M-token prompt size — what a long coding session actually pays. The endpoint behind the quote can have a smaller context window than the model; the CTX tooltip says so when that happens.
  • Off-peak discounts (TIER shows -38%, and similar): a few providers cut rates during quieter UTC hours. The main table sticks to standard rates so the ranking stays predictable, while the Off-peak deals table highlights those scheduled windows separately. Discounts never lower the ranking price, and ones that round to 0% are ignored.

What about reasoning depths and model variants?

Many newer "thinking" models let you dial in how much effort they spend reasoning before they answer — levels like minimal, low, medium, high, or max. More thinking generally lifts answer quality, at the cost of extra internal tokens and a higher bill per task.

Quality scores (QUAL) come from the Artificial Analysis (AA) intelligence index, which often benchmarks the same model across several thinking levels. Each row here is scored at the model's highest-rated depth that OpenRouter actually lets you select, and DEPTH tells you which one won (an asterisk like max* just notes that it also happens to be OpenRouter's default).

Click any row on the Picks page to unfold its full depth table — quality score, benchmark cost, and a button to copy the ready-to-use ID. In OpenCode, you pick a depth by tacking #<depth> onto the model ID, such as openrouter/deepseek/deepseek-v4.1-flash-1017#max (or #xhigh, #high, #medium, #low, #minimal, or #none). If you use the OpenCode plugin, it pins that scored depth automatically.

One more wrinkle: suffixes like :free (rate-limited free tier) and :batch (asynchronous batch jobs) are separate listings on OpenRouter with their own limits, context windows, and pricing. A :free model listing whose endpoints are all zero-priced and not themselves tagged :free/:batch is a genuinely free model and can rank; a zero-priced endpoint of a paid model is a variant, so it never sets that model's quote. :batch listings are opt-in on the command line because interactive coding needs live replies. Treat variants as distinct models — don't pair a variant ID with another row's routing block.

Why is QUAL sometimes blank?

Artificial Analysis sometimes publishes a score without saying which reasoning effort it was measured at. That score is useful as a reference, but it may not be the quality you get at any depth OpenRouter lets you select. So QUAL stays blank, DEPTH shows unknown, and the number appears only in the expanded depth table. It does not affect the ranking.

A model with no usable quality record scores zero on quality as long as at least one other model in the table has a score. If no model has any quality score, quality is left out of the ranking weights altogether, so the remaining factors decide the order.

Why are some popular models missing from the main table?

The main ranking applies a few strict filters up front so every pick is practical (and safe) for day-to-day coding work:

  • Zero-data-retention (ZDR) only: a model must have at least one live ZDR endpoint — a provider committed to not storing or training on your prompts and completions. An endpoint that only offers Safety Retention does not count: it may keep prompts and responses to investigate abuse. The site makes an exception for Google-authored models; the command-line default does not. More on that below.
  • 1M-token context window: models with smaller context limits are filtered out so long agent sessions don't hit a wall mid-task.
  • Tool calling and prompt context: the model must support tools, and the endpoint that sets its quote must itself advertise tool calling and accept the requested prompt size.
  • Endpoint policy: BYOK-only endpoints need --byok; deranked endpoints are skipped while a better default route exists; an endpoint whose provider trains on prompts is not ZDR.
  • Free listings: a zero-priced endpoint of a paid model is a variant and never the quoted endpoint. A genuinely free model (every endpoint zero-priced, including a :free listing) can still rank; a command-line option drops those if you prefer.

Need something looser for your own workflow? Those filters are configurable when you run model_compare.py on the command line — you can lower the context-window floor, include non-ZDR providers, or drop the tool-calling check. See the repository README for the options.

A model passes checks — why is it still missing?

A model can clear every filter and still drop out at the endpoint stage. The price has to come from a live endpoint that is not a :free/:batch-marked variant and not a zero-priced variant of a paid model, not a special Flex, priority, or ultrafast service tier, not below the model's baseline precision, and able to serve the run's tools and prompt size. It must also pass the endpoint-policy gates: a BYOK-only or deranked endpoint can be skipped, and a provider that trains on prompts is not ZDR. If the only endpoints left are third-party ones with an undisclosed format, or ones with a broken off-peak schedule, there is nothing to quote.

Expired listings and models that output something other than text are skipped too. The published data records only the first failed check, so a missing model may have more than one reason.

Is the model I see actually zero-retention?

In the ZDR view, yes for the quote: the price and provider order come from an endpoint on OpenRouter's ZDR list. PREC is a model-level baseline and may come from another endpoint. That is stronger than the old promise, which only required the model to have some ZDR endpoint somewhere. The match is exact: the quoted endpoint's own listing decides, and a batch or free variant cannot borrow its base model's listing. The quote must also pass the BYOK, deranked and training policy gates. It is still not a promise about calls you route yourself: the published routing keeps steered calls on ZDR endpoints as of the last snapshot, but OpenRouter's own request-level ZDR control is the live guarantee. Unsteered calls can land anywhere.

Safety Retention is not ZDR: it may keep prompts and responses to investigate abuse. The site allows it for models authored by Google; the command-line default does not. That exception is narrow — the author must be Google, not merely a model hosted on Google infrastructure. A model whose retention status is unknown is only admitted by the loosest mode.

Why do the scores change?

SCORE is relative to the current set of models. Prices are compared on a log scale (each doubling counts the same), context is compared with the 1M floor, and quality is compared with a reference intelligence score (70 by default). Add or remove one model and every score can shift, even if no price changed. Scores are not percentages. Compare ranks within one tab; don't compare scores across tabs or days.

Balanced weights quality and price at 40% each. The quality and price tabs are 60/20 in favor of quality and price respectively. Context and age are 10% each. Ties go to the higher raw quality, then the cheaper model, then the model ID.

What are the off-peak deals?

The deals table is a separate index of OpenRouter's scheduled discounts, built from the raw catalog. It deliberately does not apply the main table's ZDR, 1M-context, tool, output-text, or expiry checks, and it includes batch listings. That is why a deal can name a model that is missing from the main table.

Each row shows the cheapest off-peak window, but its SCORE is the normal balanced score from standard prices. A discount that rounds to 0% shows SCHED in the main table and is left out of the deals table. When a model has both a long-context tier and a schedule, TIER wins in the main table.

Where do QUAL and TASK$ come from?

QUAL is the Artificial Analysis intelligence index. It comes from their API when an AA API key is available, from our published catalog on an unkeyed local run, or from OpenRouter's snapshot as a last resort. The tooltip shows the source and date, and notes when AA and OpenRouter disagree by three or more points. A local run can therefore use a catalog up to two weeks old.

TASK$ is not AA's cost-per-task. It is OpenRouter's median session cost for 10–49-turn sessions, and it never affects the score.

Can free models appear?

Yes, if every endpoint is genuinely zero-priced and not itself marked :free/:batch: a free model keeps a baseline and can rank. The ZDR view still requires a ZDR endpoint, so a non-ZDR free model normally appears only in All providers (or with --no-zdr). A zero-priced endpoint of a paid model is a variant, so it never sets that model's quote. Only a handful of free models clear the 1M context floor while supporting tools. Local runs can drop them with a command-line option; the published tables keep them.

What are the ZDR and SR badges?

ZDR means the quoted endpoint is on OpenRouter's zero-data-retention list. SR means it is a Safety Retention endpoint: it may keep prompts and responses to investigate abuse, so it is not zero-retention. The badges appear in the All providers view; the ZDR view shows SR where the Google exception applies. A missing badge means the endpoint is not on the list, is on it with an undisclosed retention status, or the site had no retention data for that build.

Why can I see cheaper prices in All providers?

Because zero retention is not free. The ZDR view only quotes endpoints committed to not storing your prompts, so a cheaper provider that keeps them is out of scope; the All providers view shows that cheaper route. The difference can be large — several times the ZDR price for the same model. Expand the row to compare the live endpoint prices behind the quote.

How fresh is the site?

The site rebuilds every three hours. History keeps up to ten daily snapshots and compares exactly seven days back, within the top 20 only. The 7-DAY column is tracked for the ZDR view; the All-providers view leaves it blank. new means the model entered the top 20, not that it is new to OpenRouter. History starts blank for a week after a ranking-definition change.

If a publish check fails — a timestamp mismatch, a disagreement about the number-one pick, or a sudden endpoint drop — the previous site stays live. An old timestamp is deliberate, not a broken clock.

What about the plugin and the LiteLLM files?

The plugin pins the scored depth and steers requests to the ranked provider order, but it does not enforce ZDR. Its aliases refresh with the site, so a model can change or disappear between builds.

The LiteLLM files contain ranked models only. At most one off-peak level is used per model; if a model has both token tiers and off-peak windows, the off-peak level is left out. If two sources disagree on a price, the merge is frozen rather than guessed. Set the cost-map URL before starting LiteLLM.
